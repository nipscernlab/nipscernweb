Hardware Architecture & Toolchain

SAPHO

Scalable-Architecture Processor for Hardware Optimization

Most processors are built first and programmed later. SAPHO turns that around: you write the algorithm in C±, a small dialect of C, and the toolchain emits a Verilog processor shaped by that exact program. Word width, memory sizes, even which ALU blocks exist: everything follows from your code. Divide nowhere, carry no divider.

Every line has a price in silicon. Here it is.

Inside the generated processor, each instruction your program uses becomes a Verilog parameter set to 1; every other block is left out of synthesis entirely. A program that never divides ships without a divider. A program in integers carries no floating-point adder.

The card on the right is the moving-average filter from the manual's first processor tutorial. Flip the average between a bit shift and a division and watch the ALU change under it. In the IDE, the PRISM diagram shows the same block appearing in the actual circuit.

One button, three compilers

The Compile C± button in AURORA runs the YANC chain end to end. Each stage is an ordinary executable you could run by hand; the IDE simply never makes you.

1 · cmmcomp Translates C± into SAPHO assembly: variables placed, expressions scheduled through the accumulator, library routines appended only when called.
.cmm → .asm
2 · appcomp A first pass over the assembly. Counts instructions and data, resolves label addresses, so the single-pass assembler knows every size before emitting a word.
.asm → addresses
3 · asmcomp Assembles the program, sizes both memories exactly, and writes the processor with only the used blocks switched on. A testbench comes out with it.
→ .v + .mif + testbench

The .v and the two .mif memory images are exactly what goes to Quartus or Vivado for the real FPGA. The chain in detail · Taking it to the board.

The whole flow in one window

For graduate work the language goes further: an adaptive RLS filter is 66 lines when ⟨w|x⟩ is an expression, and an 8-point FFT loads its samples pre-shuffled because data[i) reverses the index bits in hardware.
